QNS Messenger

QNS это Android клиент и Bun сервер для защищённого обмена сообщениями.

В проекте есть:

- интерфейс Android на Jetpack Compose и Material 3
- выбор сервера перед входом
- добавление собственного HTTPS или HTTP адреса для локальной разработки
- регистрация и вход
- поиск пользователей и создание личных чатов
- список чатов, контакты, сообщения, typing и read receipts
- зашифрованный конверт сообщения на клиенте
- локальная база Room с SQLCipher
- темы System, Light, Dark и Pink Furry (розовая) с локальными boykisser-иконками
- управление активными сессиями
- серверная панель администратора
- роли user и admin, защита root-админа
- verified-галочка, beta tester, SCAM-метки с причиной
- ручное переподключение к серверу и индикатор соединения
- авто-refresh access-токена и принудительный logout при 401
- debug viewer логов для beta tester с экспортом `logcat_<timestamp>.log`
- crash-report экран после аварийного завершения
- GitHub Actions для typecheck, тестов и сборки APK

Быстрый запуск сервера

```text
cd server
cp .env.example .env
bun install
```

Заполни `.env`:

```text
PORT=3000
DB_PATH=./data/qns.db
JWT_SECRET_SEED=64_hex_symbols
ADMIN_USERNAME=admin
ADMIN_PASSWORD=StrongPassword123!
ALLOWED_ORIGINS=http://localhost:3000,http://10.0.2.2:3000
```

Сгенерировать секрет:

```text
openssl rand -hex 32
```

Создать или обновить администратора:

```text
ADMIN_PASSWORD=StrongPassword123! bun run scripts/create-admin.ts
```

Запустить:

```text
bun run dev
```

Проверка:

```text
curl http://localhost:3000/health
bun run typecheck
bun test
```

Запуск Android

```text
./gradlew assembleDebug
```

Для сервера на том же телефоне используй профиль `Этот телефон`. Он обращается к `127.0.0.1:3000`.

Для эмулятора Android используй профиль `Эмулятор Android`. Он обращается к `10.0.2.2:3000`.

HTTP для этих адресов включён только в debug варианте. Release вариант принимает только HTTPS. Для реального устройства добавь профиль с адресом компьютера в локальной сети или с публичным HTTPS адресом.

В Termux строка `^C` означает ручную остановку сервера. Запуск через `bun run src/index.ts &` оставляет процесс в фоне. Если в скопированном логе виден `&amp;`, это HTML экранирование символа `&`, а не ошибка Bun.

Выбор сервера

На экране входа есть список серверов. В release встроен production-сервер `https://mainquantumserver.onrender.com` (health: `/health`, WebSocket: `wss://mainquantumserver.onrender.com/ws`). В debug дополнительно доступны локальные адреса. Кнопка `Добавить сервер` сохраняет собственный профиль в настройках устройства. Для каждого профиля автоматически создаётся WebSocket адрес.

Если сервер изменён после входа, выйди из аккаунта и войди заново. Токены принадлежат выбранному серверу.

Панель администратора

Создай администратора через `server/scripts/create-admin.ts`. После входа с ролью `admin` в настройках появится панель администратора.

Доступны:

- статистика пользователей, сообщений, чатов и WebSocket соединений
- поиск и список пользователей
- отметка SCAM и причина
- отзыв всех сессий пользователя
- удаление аккаунта с защитой от удаления самого себя
- изменение роли или пароля через серверный API
- удаление сообщения или всех сообщений чата через API

Публичные HTTP маршруты

```text
POST   /api/auth/register
POST   /api/auth/login
POST   /api/auth/refresh
DELETE /api/auth/logout
GET    /health
```

Защищённые маршруты используют заголовок:

```text
Authorization: Bearer ACCESS_TOKEN
```

Криптография

Приватные ключи устройства сохраняются в зашифрованном хранилище Android Keystore. Сервер хранит публичные ключи и зашифрованный payload сообщения. Пароли хешируются Argon2id. Access и refresh токены подписываются Ed25519. Новые сообщения используют X3DH для установления сессии и Double Ratchet с AES-GCM; старые v1 читаются через legacy IdentityStore. Signed prekey проверяется Ed25519, identity fingerprint сохраняется для TOFU. Сервер видит только метаданные маршрутизации и зашифрованный envelope. ML-KEM/ML-DSA пока не входят в основной message flow и не должны называться постквантовой защитой.

Перед публичным запуском проверь схему обмена ключами на двух чистых устройствах. Не используй production секреты в `.env.example`.

## Механика сессии, 401 и роли

- **401 вне логина.** OkHttp Authenticator перехватывает `401`, синхронно обновляет access-токен через `POST /api/auth/refresh`, повторяет запрос. Если refresh не удался (токен отозван/истёк) или WebSocket закрыт с кодом `4001` (невалидный токен) — клиент очищает локальную сессию и показывает экран входа с сообщением «Сессия истекла. Войдите снова.».
- **Root admin.** Админ из `.env` помечается `is_root_admin`. Его нельзя удалить, понизить, пометить SCAM или отозвать его сессии ни через UI, ни через API (сервер возвращает `403`). Других админов можно менять по обычным правилам.
- **Verified** (`is_verified`) и **beta tester** (`is_beta_tester`) выставляются админом в панели. `isVerified` показывается галочкой в списке чатов, контактах, чате и админке; `isBetaTester` открывает debug viewer логов (только в debug-сборке).
- **SCAM.** Причина метки хранится на сервере (`scam_reason`), возвращается API и показывается в профиле/чате/контактах/админке. Если причины нет — «Причина не указана».
- **Logout** очищает локальные сообщения, чаты, ratchet-сессии и кэш расшифровки текущего аккаунта.

## Экран ключа безопасности (TOFU)

Отпечаток `fingerprint = SHA-256(localIdentityPublic ‖ remoteIdentityPublic)` (сортировка стабильная) показывается по тапу на замок в шапке чата. При изменении identity-ключа собеседника клиент не отправляет сообщение молча и показывает предупреждение о возможной переустановке приложения или атаке.

## Furry-тема

Розовая тема заменяет основные Material-иконки на локальные boykisser-картинки (5 штук в `res/drawable`). Выбор картинки детерминирован по имени иконки — при каждой recomposition иконка не «мигает». В обычных темах используются стандартные Material icons. Сеть при этом не грузится.

## Безопасность и режимы сборки

В release запрещены локальные HTTP-профили и debug log viewer; production по умолчанию — `https://mainquantumserver.onrender.com`. В debug beta-тестеру доступен viewer логов с экспортом файла `logcat_<timestamp>.log`. Логи не содержат пароли, токены, приватные ключи или plaintext сообщений. Root admin, verified, beta tester и scam reason проверяются сервером, а не только UI. После logout приложение очищает локальные сообщения и состояние ratchet текущего аккаунта.

Изменения схемы сервера применяются idempotent-миграциями при старте; Room использует миграцию 1→2 для локальной базы.
